# Передача дневника питания Natrium

## Граница пакета

Пакет подготовлен для применения к чистому checkout репозитория на базовом коммите `d13371a246d0dc223cafe736f10541e4bec9a6c2`. Он содержит только новые файлы дневника питания и три изменённых существующих файла: `src/telegram_bot.py`, `.env.example`, `.gitignore`.

Локальная автоматическая приёмка завершена: `64 passed, 0 failed, 0 skipped` за `0.58s`. Она использовала временную SQLite, синтетические Telegram updates, фиктивные ответы AI и поддельные исходящие вызовы.

Не проверены настоящий Telegram Bot API, OpenAI API, HTTP и Telegram Mini App, живой сервер Oracle и production deployment. Пакет нельзя считать выпущенным до прохождения этих проверок в целевой среде.

## Подготовка выпуска

1. Создать чистый checkout на коммите `d13371a246d0dc223cafe736f10541e4bec9a6c2`. Если удалённая ветка уже ушла вперёд, сначала перенести изменения на её актуальную вершину и повторить проверки.
2. На живом сервере сохранить текущую версию изменяемых файлов, действующий commit SHA и конфигурацию. Секреты не переносить в пакет и не выводить в журнал.
3. Сделать согласованную резервную копию рабочей SQLite через SQLite backup API. Полученный файл самодостаточен: отдельно копировать к нему WAL/SHM работающей базы не нужно. Не удалять и не заменять живую базу при применении кода.
4. До перезапуска вызвать Telegram `getMe` с действующим токеном и проверить точное значение `username == "natrium_smm_bot"`. Токен и полный URL запроса не журналировать.
5. Распаковать архив поверх чистого checkout с сохранением относительных путей. Проверить SHA-256 каждого файла по `manifest.json`.
6. Настроить переменные из `.env.example`. Внешнюю панель оставлять выключенной, пока не готовы HTTPS origin и allowlist: `NUTRITION_DASHBOARD_ENABLED=0`.
7. Выполнить локальные проверки в окружении проекта:

```bash
python3 -m py_compile src/telegram_bot.py src/nutrition_store.py src/nutrition_ai.py src/nutrition_bot.py src/nutrition_dashboard.py
python3 -m pytest tests/test_nutrition_*.py -q
```

8. Выполнить штатный deployment проекта без изменения его схемы доставки. После запуска проверить состояние процесса, повторить безопасный `getMe`, пройти `/start` и открыть `🥗 Дневник питания` в личном чате.
9. Отдельно проверить ручной ввод, согласие перед фото, ошибку AI с переходом к ручному пути, подтверждение без дубля, день и неделю, смену часового пояса, привязку тренера и запрет доступа к чужому клиенту.

## Проверка панели

Панель включается только после настройки HTTPS origin и allowlist. После этого нужно проверить подпись и срок Telegram `initData`, доступ только к привязанным клиентам, изменение норм и записи, комментарий тренера и безопасный вывод пользовательского текста. Локальный HTTP-ответ сам по себе не подтверждает готовность Mini App.

## Откат

При ошибке остановить штатный процесс, вернуть сохранённую версию файлов и прежний commit штатным способом проекта, восстановить прежнюю конфигурацию и снова запустить сервис. После отката проверить процесс и `getMe`.

Живую SQLite при откате кода не удалять. Восстанавливать данные из резервной копии только при подтверждённом повреждении или несовместимости. Перед восстановлением остановить приложение и сохранить проблемную базу вместе с её WAL/SHM отдельно для разбора. Самодостаточную копию, созданную через SQLite backup API, не смешивать с WAL/SHM другой версии базы.

Состав пакета, базовый commit, размеры и SHA-256 файлов записаны в `staging/nutrition-release-20260907/manifest.json` рядом с архивом.
